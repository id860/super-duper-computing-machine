# Архитектура PixelFront Worlds v3

## Runtime

PixelFront Worlds — автономный Node.js-монолит: HTTP API, JSON Store, SSE и SPA на ванильном JavaScript. Внешние сервисы (PostgreSQL, Redis, worker) — opt-in и включаются переменными окружения.

```text
Browser SPA ── fetch / EventSource ──> server-v3.mjs
  main.js + experience-patch.js          ├─ api.mjs + player-preferences.mjs
  engine.js + interaction-patch.js       ├─ world-bootstrap.mjs + chunks.mjs
  viewport-cache.js + chunk-lru.js       ├─ metrics.mjs (/api/health, /api/metrics)
  chunk-prefetch.js + chunk-store.js     ├─ src/core/* + JSON Store
  tile-grid.js + render-tiles.js         ├─ postgres-mirror.mjs (DATABASE_URL)
  minimap-nav.js                          └─ redis-runtime.mjs (REDIS_URL) ↔ worker-v3.mjs
```

## Клиент

Порядок подключения модулей важен: каждый патч расширяет прототип `PixelEngine`, поэтому загрузчик чанков объявлен ровно один раз — в `chunk-prefetch.js`.

- `engine.js` — canvas, зум, панорамирование, базовый renderer и миникарта.
- `interaction-patch.js` — визуальные инструменты и жесты.
- `viewport-cache.js` + `chunk-lru.js` — LRU загруженных чанков и вытеснение самих пикселей дальних чанков (свежие записи сохраняются).
- `chunk-queue.js` — чистая геометрия очереди: центр вьюпорта, кольца и минимальный недогруженный радиус.
- `chunk-store.js` — IndexedDB-кэш чанков (TTL 6 часов), безопасные no-op без IndexedDB.
- `chunk-prefetch.js` — единственный загрузчик: дебаунс, кэш до сети, кольца `0 → 1 → 2`, LRU-учёт.
- `tile-grid.js` + `render-tiles.js` — тайловый конвейер `64 × 64` на offscreen-канвасах.
- `minimap-nav.js` — клик и перетаскивание по миникарте с pointer capture.
- `experience-patch.js` — профиль и гардероб, косметика всех авторов чата, витрина событий, зона спавна и панель.
- `main.js` / `ui.js` — маршрутизация, панели, SSE, инструменты и модалки.

## Рендер

Кадр больше не перебирает всю карту. Пиксели раскладываются по тайлам `64 × 64`, каждый тайл рисуется в свой offscreen-канвас и кэшируется (до 320 тайлов). Кадр — это композиция видимых тайлов. Локальное рисование и SSE помечают грязными только затронутые тайлы; смена мира, зума или вытеснение чанков инвалидируют всю сетку.

## Бесконечный мир и чанки

Официальный мир имеет диапазон `0…99 999` и стартовую зону `1000 × 1000`. Она рендерится как лёгкая заливка с подписью, может скрываться в настройках игрока и не мешает работе с холстом.

Infinite bootstrap не передаёт полный массив пикселей. Серверный `ChunkIndex` индексирует их в памяти по fine-чанкам **86 × 86** (старый 256-клеточный участок разделён на `3 × 3`).

Клиент грузит центральный чанк первым, затем расширяет окно кольцами `radius=1` и `radius=2`, пока камера стоит на месте. Запросы коалесируются через короткий дебаунс, а ответы пишутся в IndexedDB: при возврате в уже посещённую область картинка появляется до сетевого ответа.

`CHUNK_READ_MODE` выбирает источник: `auto` (по умолчанию) читает из `world_chunks`, когда зеркало подключено, `json` принудительно оставляет индекс в памяти, `postgres` — явный алиас `auto`. Любая ошибка чтения прозрачно возвращает запрос на JSON-индекс, а поле `storage` в ответе всегда показывает фактический источник.

## Синхронизация и безопасность

Canvas применяет операции оптимистично; сервер проверяет координаты, энергию, роли, защиту и rate limits, затем передаёт SSE. CSRF, Origin checks, CSP, scrypt-пароли и защита статики действуют на уровне HTTP.

С `REDIS_URL` сессии и rate limits становятся общими для всех инстансов, а SSE-события рассылаются через канал `pixelfront:sse`.

## Профиль и экономика

Косметика хранится отдельно от инвентаря в независимых слотах (`frame`, `nick`, `badge`, `trail`, `cursor`): рамку, оформление ника и значок можно использовать одновременно. `GET /api/me/preferences` отдаёт `cosmetics.equipped` и `cosmetics.owned`, поэтому гардероб в профиле рисует живые превью теми же классами, что и чат. История чата отдаёт слоты авторов, а живые сообщения добирают их через `GET /api/cosmetics?nick=`. Карточки событий раскрываются и показывают цель, личный прогресс, награду и оставшееся время.

## Наблюдаемость

`src/http/metrics.mjs` отвечает на `GET /api/health` и `GET /api/metrics` до rate-лимитера, чтобы пробы не получали `429`. Ответ собирает счётчики Store (миры, активные миры, игроки, сессии, пиксели, сообщения, аудит) и runtime-данные: uptime, число SSE-клиентов, RSS, режимы `storage` и `automation`. Личные данные не раскрываются.

## Deployment and scale-out

JSON остаётся автономным runtime и безопасным fallback. Порядок rollout: dual-write → импорт через `scripts/export-postgres.mjs` → чтение чанков из PostgreSQL (режим `auto`) → Redis-сессии и fan-out → `AUTOMATION_MODE=worker` с отдельным `worker-v3.mjs`. Откат — `CHUNK_READ_MODE=json` или снятие соответствующей переменной окружения. Детали и переменные — в `infra/README.md` и `.env.example`.

## Verification

GitHub Actions на каждый push в `main` выполняет syntax-check клиентских и серверных модулей, unit/live API-контракты (тайловая сетка, очередь чанков, навигация миникарты, метрики, косметика в чате, режимы чтения чанков) и Docker build. Отдельный workflow `Load` запускается по расписанию (03:20 UTC) и вручную, гоняя нагрузку чанков и контракты потока.
