# Архитектура PixelFront Worlds

## Обзор

PixelFront Worlds — монолит на Node.js без внешних runtime-зависимостей: HTTP API, JSON-хранилище, SSE и браузерное SPA на ванильном JavaScript.

```text
Browser SPA ── fetch / EventSource ──> server-v3.mjs
   main.js  ─┐                         ├─ src/http/api.mjs
   api.js   ─┼─ canvas + UI             ├─ src/http/kit.mjs
   engine.js ┤                         ├─ src/http/sse.mjs
   ui.js    ─┘                         └─ src/core/*
```

## Слои

### Клиент — `public/app/`

| Файл | Назначение |
|---|---|
| `main.js` | boot, hash-маршрутизация, панели, SSE, тултип автора пикселя |
| `api.js` | fetch-обёртка и CSRF |
| `engine.js` | canvas-рендер, зум к курсору, панорамирование, pinch, миникарта |
| `ui.js` | инструменты, палитра, hotkeys, локальный undo, модалки и тосты |

### Сервер — `src/http/`

| Файл | Назначение |
|---|---|
| `api.mjs` | HTTP-маршруты, авторизация и бизнес-правила |
| `kit.mjs` | сессии, CSRF, security headers, JSON и статика |
| `sse.mjs` | поток `pixels`, `chat`, `lifecycle`, `reload` |

### Ядро — `src/core/`

| Файл | Назначение |
|---|---|
| `model.mjs` | модель мира и пользователя, пресеты, миграции |
| `progress.mjs` | уровни, XP, квесты, магазин, рейтинги |
| `rules.mjs` | роли, защита, энергия, антиспам |
| `automation.mjs` | события, сезоны, жизненный цикл, очередь |
| `db.mjs` | атомарный JSON-стор c дебаунсированной записью |

## Бесконечный официальный мир

Официальный мир имеет `infinite: true` и доступный диапазон координат `0…99 999` по каждой оси. Его стартовая зона — квадрат **1000 × 1000** (`0…999 × 0…999`). Движок показывает границу пунктирной синей рамкой; эта область даёт повышенное XP.

### Производительность холста

- Пиксели представлены разрежённой `Map`, где ключ — `x:y`, а значение — `{ c, nick, at }`.
- На кадре отрисовываются только установленные пиксели внутри вьюпорта, а не вся поверхность мира.
- `requestAnimationFrame` коалесцирует повторные запросы рендера при панорамировании и зуме.
- Миникарта использует офскрин-буфер и пересобирается лишь при изменении данных или выходе вьюпорта за известные границы.
- Информация об авторе появляется с задержкой при наведении: сначала используется SSE-кэш, затем `pixel-info` только при необходимости.

## Рисование и синхронизация

Клиент применяет штрих оптимистично и отправляет операции пачками с короткой задержкой. Сервер заново валидирует цвет, клетки, энергию, роли, защиту и rate limits. После применения сервер рассылает SSE-событие с ником автора. Локальный undo восстанавливает предыдущие цвета и отправляет обратные операции как обычные пиксельные записи.

## Безопасность

| Механизм | Реализация |
|---|---|
| CSRF | `x-csrf-token` для всех mutating-запросов и Origin-проверка |
| Headers | CSP, `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, COOP |
| Пароли | `scrypt` |
| Rate limits | процессные лимитеры для регистрации, входа, чата и рисования |
| Файлы | защита от path traversal в статическом сервере |

## Данные и масштабирование

Данные находятся в `DATA_DIR/db.json`; запись выполняется через временный файл и rename. Текущая модель хорошо подходит для MVP и умеренного числа пикселей. Следующий технический этап: разбиение пикселей по чанкам, пространственный индекс, PostgreSQL и Redis для горизонтального масштабирования.
