# Архитектура PixelFront Worlds

## Обзор

PixelFront Worlds — Node.js-монолит без внешних runtime-зависимостей: HTTP API, JSON-хранилище, SSE и браузерное SPA на ванильном JavaScript.

```text
Browser SPA ── fetch / EventSource ──> server-v3.mjs
   main.js  ─┐                         ├─ api.mjs + world-bootstrap.mjs
   api.js   ─┼─ canvas + UI             ├─ chunks.mjs + sse.mjs
   engine.js ┤                         └─ src/core/*
   ui.js    ─┘
```

## Слои

### Клиент — `public/app/`

| Файл | Назначение |
|---|---|
| `main.js` | boot, hash-маршрутизация, панели, SSE, тултип автора пикселя |
| `api.js` | fetch-обёртка, CSRF и загрузка infinite-мира через viewport bootstrap |
| `engine.js` | canvas-рендер, зум, панорамирование, pinch, миникарта |
| `interaction-patch.js` | исправление миникарты, иконки, загрузчик/кэш viewport-чанков |
| `ui.js` | инструменты, палитра, hotkeys, undo, модалки и тосты |

### Сервер — `src/http/`

| Файл | Назначение |
|---|---|
| `api.mjs` | HTTP-маршруты, авторизация и бизнес-правила |
| `world-bootstrap.mjs` | метаданные infinite-мира без полного массива пикселей |
| `chunks.mjs` | чанки 256×256 и пространственный индекс мира |
| `kit.mjs` | сессии, CSRF, security headers, JSON и статика |
| `sse.mjs` | поток `pixels`, `chat`, `lifecycle`, `reload` |

## Бесконечный официальный мир

Официальный мир имеет `infinite: true` и диапазон координат `0…99 999` по каждой оси. Стартовая зона — **1000 × 1000** (`0…999 × 0…999`), показанная пунктирной синей рамкой; в ней действует повышенный XP.

## Производительность

- Рендерер хранит пиксели в разрежённой `Map` и рисует только клетки в текущем вьюпорте.
- rAF коалесцирует повторные кадры при панорамировании и зуме.
- Миникарта использует офскрин-буфер, корректно включает отрицательные координаты камеры и обновляется только при изменениях.
- Infinite-мир открывается через metadata bootstrap: первоначальная полезная нагрузка не содержит полного массива пикселей.
- После bootstrap клиент запрашивает центр и соседние чанки; пустые чанки кэшируются.
- Сервер индексирует пиксели по чанкам `256×256` в памяти и синхронизирует индекс после применённых операций.
- Hover сначала использует SSE-кэш автора, затем вызывает `pixel-info` только при необходимости.

## Рисование и синхронизация

Клиент применяет штрих оптимистично и отправляет операции пачками. Сервер заново валидирует цвет, клетки, энергию, роли, защиту и rate limits. `brush2` и `brush3` ограничены фактическими размерами 4 и 9 клеток; настройки старых миров нормализуются на старте. После применения сервер рассылает SSE-событие с ником автора.

## Безопасность

| Механизм | Реализация |
|---|---|
| CSRF | `x-csrf-token` для mutating-запросов и Origin-проверка |
| Headers | CSP, `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff` |
| Пароли | `scrypt` |
| Rate limits | процессные лимитеры для регистрации, входа, чата и рисования |
| Файлы | защита от path traversal в статическом сервере |

## Масштабирование

JSON-хранилище остаётся MVP-слоем. Уже реализованы viewport chunks и пространственный индекс. Следующий инфраструктурный этап — вынести пиксели в PostgreSQL (таблица по `(world_id, chunk_x, chunk_y)`), состояние/лимиты и fan-out в Redis, а фоновые задания — в отдельный worker.

## Проверка

GitHub Actions выполняет syntax-check серверных модулей, unit-контракты модели, чанков, compatibility-миграций и metadata bootstrap, затем Docker build.
