# PixelFront Worlds

Автономная многопользовательская пиксельная платформа: официальный **бесконечный** мир с честной прогрессией и настраиваемые миры сообщества без влияния на глобальный рейтинг.

## Реализовано в v3

- Бесконечный официальный холст: виртуальная область `100 000 × 100 000`, стартовая зона `1000 × 1000` и XP ×2 внутри неё.
- Минималистичный интерфейс, SVG-инструменты, горячие клавиши, undo, пиксельный tooltip и сворачиваемая боковая панель.
- Исправленная миникарта: корректно отображает камеру и при движении влево/вверх.
- Разрежённый canvas-рендер, rAF-коалесинг, офскрин-мини-карта.
- **Viewport-загрузка:** бесконечный мир открывается без полного массива пикселей; клиент получает стартовые чанки `256×256` и подгружает соседние при панорамировании.
- Серверный spatial index по чанкам, синхронизируемый после каждой принятой пиксельной операции.
- JSON-персистентность, SSE, CSRF, rate limit, роли, админка, Docker и GitHub Actions.

## Локальный запуск

```bash
cp .env.example .env
# Задайте ADMIN_NICK и ADMIN_PASSWORD
set -a && source .env && set +a
npm start
```

Откройте `http://localhost:3000`.

## Docker Compose

```bash
cp .env.example .env
# Укажите надёжный ADMIN_PASSWORD
# При внешнем домене задайте APP_ORIGIN=https://example.com
docker compose up -d --build
```

Compose запускает `server-v3.mjs` и хранит JSON-данные в именованном томе `pixelfront-data`.

## Тесты

```bash
npm test
```

Контракты включают модель, compatibility-миграцию кистей, spatial index, metadata bootstrap infinite-мира и live-интеграцию server-v3: регистрация, CSRF, операция рисования и загрузка чанка.

## Правило прогрессии

XP, достижения и глобальный рейтинг начисляются только при `world.type === "official"`. Пиксели зоны `(0…999, 0…999)` дают двойной XP. Пиксели пользовательских миров учитываются отдельно.

## Следующая инфраструктурная ступень

Текущий JSON-store и in-memory индекс подходят для MVP. Для горизонтального масштабирования данные пикселей нужно перенести в PostgreSQL с ключом `(world_id, chunk_x, chunk_y)`, сессии/rate limits и SSE fan-out — в Redis, а автоматизацию — в отдельный worker.
